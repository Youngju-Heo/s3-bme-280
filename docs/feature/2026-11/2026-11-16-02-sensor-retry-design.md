## 의도

SPI 센서 통신이 간헐적으로 실패한다(부팅 #61~#83 실패, #84·#90 정상, 실패 시 chip ID는 항상 `0x00`). 지금은 부팅 때 초기화에 한 번 실패하면 리셋할 때까지 빨간불이 유지되어, 잠깐의 접촉 불량이 장시간 기록 누락으로 이어진다. 이 작업은 다음 세 가지를 한다.

- 접점 저항이 커진 경계 상태에서도 통신 여유를 확보한다.
- 실패하면 스스로 회복을 시도한다.
- 자동 회복 중인 오류와 손을 써야 하는 오류를 LED로 구분한다.

## 목표 / 비목표

- 목표: SPI 1 MHz, 실패 후 다음 측정 주기에 재초기화 후 측정, LED 빨강 깜빡임(재시도 중)과 빨강 고정(SPI 버스 초기화 실패 또는 플래시 저장 실패) 구분, 문서 갱신.
- 비목표: CLI·웹에 "재시도 중" 문구 표시(원인은 `sensor_error`로 이미 보임), 측정 주기와 별도인 빠른 재시도 타이머, `spi_init` 재시도.
- 안티목표: 정상 동작 시의 측정·기록·LED가 달라지는 것.

## 접근 방식

| 안 | 내용 | 판단 |
|---|---|---|
| **A (선택)** | 직전 시도(초기화든 측정이든)가 실패했으면 다음 측정 주기에 재초기화 후 측정. 샘플러가 담당 | 간헐 접촉과 센서 전원 순간 끊김(설정 초기화 → 습도 오기록)을 모두 덮는다. 재시도가 측정 시점에 있으므로 접촉이 돌아온 주기의 기록이 남는다 |
| B | 부팅 시 초기화 실패만 재시도 | 전원 순간 끊김 뒤 재설정 없이 읽는 문제가 남는다 |
| C | 별도 타이머로 짧은 간격 재시도 | 잠금·동시성 처리가 늘지만, 기록은 측정 주기에만 남으므로 이득이 적다 |

SPI 클럭은 10 MHz에서 1 MHz로 낮춘다. 접점 저항과 배선 정전용량이 만드는 RC 시정수 허용치가 약 10배 늘어난다. 완전 단선은 재시도가, 경계 상태는 클럭 하향이 맡는다.

## 결정 사항

- **재시도 규칙:** 측정 주기가 돌아왔을 때 직전 결과 코드가 `BME280_OK`가 아니면 `bme280_init`을 먼저 수행하고, 성공하면 이어서 측정한다. 초기화 실패도 실패 결과로 기록한다(rc, chip ID). SPI 버스 초기화 실패(`spi_init`)는 재시도하지 않는다.
- **`sensor_error`·`sensor_chip_id`:** 재시도 결과로 갱신된다. "부팅 시 초기화 실패 원인은 리셋 전까지 유지" 규칙은 없어진다.
- **측정마다 습도 설정 재기록:** `bme280_read`는 매 측정마다 `CTRL_HUM`을 다시 쓴 뒤 `CTRL_MEAS`(forced)를 쓴다. 측정 사이에 센서 전원이 순간 끊겨 설정이 초기화돼도 다음 측정이 스스로 복원한다(재시도는 측정 시점에 실패로 관측된 경우를 맡는다).
- **`read_now`:** 직전 초기화·측정이 성공한 상태에서만 센서를 읽는다. 그 밖에는 지금처럼 `sensor_error`로 응답한다.
- **LED:**

| 상태 | 표시 |
|---|---|
| 센서 실패, 자동 재시도 중 | 빨강 깜빡임 (0.5초, 기존 깜빡임과 같은 주기) |
| `spi_init` 실패 또는 플래시 저장 실패 | 빨강 고정 |
| 둘이 겹치면 | 빨강 고정 (더 심각한 쪽) |

  빨강은 지금처럼 WiFi 파랑보다 우선한다. 녹색·파랑 표시는 그대로다.

## 네이밍

| 대상 | 이름 |
|---|---|
| LED 상태 | `STATUS_LED_ERROR_RETRYING` (빨강 깜빡임), 기존 `STATUS_LED_ERROR`는 빨강 고정 |
| 샘플러 | `bool sampler_sensor_ready(void)`: 직전 초기화·측정 성공 여부(`read_now` 허용 판단), `bool sampler_sensor_retrying(void)`: 센서 실패 중이고 재시도 대상(버스 있음)인지 |
| `sampler_init` | 시그니처 유지. `sensor`는 SPI 버스가 정상이면 초기화 실패여도 non-NULL, `spi_init` 실패 시에만 NULL |
